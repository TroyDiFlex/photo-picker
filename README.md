# Фото по артикулу

Одностраничный сайт для списка артикулов: Google Диск, фотографии eBay, галочки, имена папок из TXT, скачивание одним ZIP. Суффикс VRN, Markdown-таблицы и обратные слеши в конце строк убираются автоматически.

Сайт рассчитан на GitHub Pages. Покупать сервер или держать компьютер включённым не требуется. Зависимости не устанавливаются.

## Текущее состояние

- Код интерфейса, клиента Google Диска и получения фотографий eBay подготовлен.
- Google OAuth Client ID и опубликованный адрес подключения eBay пока не настроены.
- Страница опубликована: https://troydiflex.github.io/photo-picker/ . GitHub Pages вернул `built`, HTML и JavaScript-модули отвечают HTTP 200 с подходящими MIME-типами.
- Прямые запросы eBay с текущего подключения получают HTTP 403. Работа из Google Apps Script не проверена. Наличие кода не означает, что eBay уже отдаёт реальные фотографии.
- Вход Google и реальный поиск в закрытой папке не проверены без авторизации пользователя.
- Браузерная и визуальная проверки не выполнялись: управление браузером не разрешено.
- Все 25 автоматических тестов прошли. Проверки закрытого Диска используют подставные ответы и не заменяют реальный вход Google; проверки eBay-парсера используют HTML-примеры и не подтверждают текущую разметку сайта.

## Как пользуются посетители

Открывают сайт, входят через свой Google-аккаунт, вставляют артикулы и выбирают файлы. Чужой аккаунт владельца сайта посетителям не передаётся. Если у человека нет доступа к папке, приложение сообщает об отсутствии доступа. Это отличается от успешного поиска, при котором фотографий действительно нет: только во втором случае автоматически открывается вкладка eBay.

Настройки в `public/config.js` задаёт владелец один раз. Посетителям не нужно заполнять Client ID или адрес подключения. Локальное изменение настроек доступно для проверки и сохраняется только в текущем браузере; токен Google в хранилище не записывается.

## Однократное подключение Google

Требуется Google Cloud проект с включённым Google Drive API и OAuth-клиентом типа Web application. Это настройка приложения, пароль Google или client secret странице не нужны.

1. Настроить экран согласия Google OAuth. Для небольшого теста добавить Google-адреса участников в список тестовых пользователей.
2. Добавить точный адрес GitHub Pages (`https://OWNER.github.io`) в Authorized JavaScript origins. Для локальной проверки добавить `http://localhost:8787` или `http://127.0.0.1:8787`.
3. Записать публичный Client ID в `public/config.js`, поле `googleClientId`.
4. Открыть страницу, войти своим аккаунтом и проверить несколько настоящих артикулов.

Разрешение `drive.readonly` технически предоставляет чтение доступного аккаунту Диска целиком. Приложение отбирает результаты для заданной папки. Google не предоставляет этому OAuth-разрешению ограничение ровно одной папкой. Возможность изменения/удаления файлов не запрашивается. Для широкого публичного использования могут понадобиться проверка приложения Google и выполнение её требований; тестовый режим не равнозначен публикации для всех.

## Подключение eBay без аренды сервера

Файлы `google-apps-script/Code.gs` и `google-apps-script/appsscript.json` подготовлены для Google Apps Script. Это обработка публичных страниц eBay в среде Google, без официального eBay API. Единственное разрешение скрипта - `script.external_request`. Он не использует Google Drive и не получает пользовательские токены.

1. Создать отдельный проект в `https://script.google.com/`.
2. Перенести `Code.gs` и манифест `appsscript.json`.
3. Опубликовать Web app: Execute as Me, доступ Anyone. Скрипт обращается только к eBay; разрешения на чтение Диска в его манифесте нет.
4. Проверить `/exec?action=health`, затем `/exec?action=search&article=038145209&page=1`.
5. Только при получении настоящих карточек/фотографий записать адрес `/exec` в `public/config.js`, поле `backendUrl`.

Открытый скрипт отдаёт только публичные материалы eBay. Его вызовы расходуют квоты Google аккаунта, который разместил скрипт. Приватные файлы Google Диска через него не проходят. Запросы из браузера используют JSONP, предусмотренный Google Content Service; поэтому указывать нужно только доверенный собственный адрес скрипта. eBay может ограничить и запросы из Google. Ошибки блокировки отображаются явно; автоматический обход CAPTCHA не реализован.

Обработчик генерируется из общих парсеров: `node scripts/build-apps-script.mjs`. Команда использует только стандартную библиотеку Node и ничего не скачивает.

## Публикация на GitHub Pages

Исходники хранятся в ветке `main`, на Pages отправляется только содержимое `public/` в ветке `gh-pages`. Репозиторий публичный, секретов в настройках нет. GitHub CLI должен быть авторизован. Скрипт `scripts/publish.ps1` создаёт репозиторий и включает Pages после авторизации; ничего не устанавливает. При повторном запуске использует уже привязанный origin и проверяет владельца/имя.

```powershell
.\scripts\publish.ps1
```

## Проверки и локальная разработка

```powershell
node --test tests/*.test.mjs
node server.mjs
```

`server.mjs` нужен только для локальной разработки и проверок. Его не требуется размещать для варианта с Apps Script. При локальном запуске доступна страница `http://127.0.0.1:8787`.

Архив формируется в браузере без ZIP-библиотек, имена сохраняются в UTF-8. Дубликаты имён разделяются, недопустимые для Windows символы очищаются. Лимит одного архива - 512 МБ; большие выборки нужно разбить. Ошибка загрузки одного файла прерывает сборку, неполный архив не выдаётся за успешный. TXT распознаётся в UTF-8, Windows-1251, UTF-16. Наименование берётся из строки `Наименование:`/`Название:` либо из первой подходящей непустой строки; название можно исправить вручную.

Видео и текстовые файлы видны как отдельные карточки и открываются на Диске. Изображения на Диске крупнее 12 МБ показываются карточкой со ссылкой без миниатюры. Точный формат реальных TXT и содержимое папки нужно проверить после входа.
